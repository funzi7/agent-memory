## The incident this fixes
Scheduled Daily run **31848205965** (run #71, 2026-08-14T22:51:11Z, head `a772d40`) went RED with
`main.py → engine.run_day → engine.py:540 close = _price_at(window[tk], …) → KeyError: 'CELH'`.
The crash fired **before** report/Telegram/commit, so there was no Telegram Daily and no state
commit — hence production stuck at 2026-08-07. (The 14 delisted-ticker download failures + the
twitterapi.io HTTP 402 in the log are pre-existing NON-fatal noise; Telegram secrets were present
— NOT a secret issue.)

## Root cause (architectural invariant violation, NOT a CELH-specific bug)
`screener_track` rebalances **MONTHLY**. On 2026-08-02 the shortlist held CELH; the 2026-08-09
weekly `screener_picks.yaml` dropped CELH. The portfolio legitimately KEPT holding CELH (monthly-
only rebalance). But `required_tickers(strategies)` is built from each strategy's CURRENT
`tickers()`, and `ScreenerTrack.tickers()` returns only the current shortlist — so CELH stopped
being requested from the data layer even though it was an OPEN position, and `run_day` KeyError'd
on `window["CELH"]` while aging it. `main.py` only special-cased held/pending for `swing`/
`pullback`; the invariant was not general.

## The fix (code + tests only — no strategy/accounting/workflow changes)
- **`main.py`** — `held_tickers_all()` / `pending_tickers_all()` compute `live_state` = held
  positions ∪ pending orders across ALL real portfolios. `live_state` is added to the fetch list
  (yfinance+Stooq) so those names are always requested. Strategy-AGNOSTIC — no `if ticker==…`,
  no new per-strategy case — so it also protects future dynamic strategies (`guru_track`/
  `twitter_track`/…). A clean **pre-engine data-integrity boundary** splits a core miss into
  `live_missing` (held/pending) vs `other_missing` (fixed instruments): a held/pending name
  missing from BOTH sources prints a precise diagnostic naming the ticker(s) and returns
  **non-zero BEFORE any migration/fill/date-advance/state-or-trade write** — no partial
  processing, no fabricated/borrowed price, no liquidation on a transient gap. Broad UNHELD
  candidate universes stay SOFT (non-fatal). On the executing paths (normal daily + no-new-bar
  first-scan) the full `live_state` is required; the `--recompute-pending` maintenance path (no
  `run_day`) keeps its historical narrower requirement so a dataless unrelated holding never
  blocks the rebuild. The early-alert Telegram send is now best-effort (try/except) and logs
  ONLY the exception type — a `requests` error embeds the `…/bot<TOKEN>/` URL, so the old
  `str(exc)` would leak the bot token into the CI log (same scrub applied to the end-of-cycle
  report handler).
- **`tests/selftest.py`** — `test_live_state_data_invariant` T1–T7 (exact CELH regression incl. a
  direct `KeyError('CELH')` repro; guru/twitter generality; pending-order invariant; genuine
  missing live-state → controlled non-zero, named, no state/trade mutation; Telegram-fails-during
  -alert with a bot-token-scrub assertion; SOFT-universe miss non-fatal; recompute not blocked by
  a dataless holding) + `test_gap_multisession_advance` (E2E gap: no replay, one equity point,
  stale pending fills once, honest 12-day note). Replaced a brittle source-string pullback check
  with behavioral helper checks.
- **`handoffs/CONTEXT.md`** — new §5p (incident, invariant, controlled-failure, recovery) + §11
  status, in the same commit.
