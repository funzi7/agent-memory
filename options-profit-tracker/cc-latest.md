### Unique-match / ambiguity behavior (`IbkrReconciler`)
- Closed cycle: candidates = non-draft rows on the same ticker/type/strike/expiry/direction → rows with the SAME contract count; exactly one → match; several → by openDate, then closeDate; still several → **Ambiguous (no write, `IBKR_RECON AMBIGUOUS …` log)**. No same-count row → the single MANUAL row whose openDate is within 5 days of the broker open (owner's quantity was approximate); several → Ambiguous; none → None. IMPORTED rows with a different quantity are never guessed.
- Open cycle: exactly one OPEN row on the contract → match (quantity may be corrected); several → Ambiguous.
- Partial cycles keep the existing FN1 slice/remainder handling.
- Idempotent (unchanged rows are not rewritten); runs in `doImport` for both incremental sync and full resync (same `doImport`). Diagnostics carry contract identity only (no account ids / raw XML). `ImportState.debugInfo` gets "IBKR recon: N updated, M ambiguous".
